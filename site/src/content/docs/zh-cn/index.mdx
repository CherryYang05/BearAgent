假设你让 Agent 阅读一个仓库，并把结论写到 `outputs/report.md`。模型会决定下一步，但它不应该
直接决定哪些文件能读、哪些位置能写，也不能在一次调用超时后猜测文件是否已经写好。BearAgent
要把这些执行问题放到模型之外处理。

:::caution[BearAgent 还不能完成真实 Agent 任务]
当前代码已经能表示消息、错误、Run、Activity 和 Event，也能从一串 Event 计算状态并检查预算。
Event 可以原子写入 SQLite，OpenAI Responses adapter 也能翻译流式响应，四个 workspace Tool 能在
统一权限入口后读文件或原子写 `outputs/**`；但 ContextBuilder、完整执行循环、Tool Event 接线和
Run CLI 仍未接通。路线图中的名称不是当前功能。
:::

## BearAgent 想把三件事做可靠

1. **执行过程能还原。** 用户可以知道模型和工具做过什么、用了多少预算、在哪里失败。
2. **结果不明时不猜。** 已确认的操作可以继续使用；无法确认的外部写入会停下来处理。
3. **权限不由模型决定。** 模型可以提出工具请求，但 Runtime 才能允许、询问用户或拒绝。

第一版只做仓库和本地文档研究，并且只允许向 `outputs/**` 写入。这个范围很小，正好可以把
记录、失败和权限做实，再考虑 Web、MCP、Memory 或多个 Agent。
